# Interactive House Map for Home Assistant

A React floorplan dashboard for Home Assistant: tap a room to zoom in and control its lights, temperature, blinds, and cleaning — plus an overview panel with weather, an alarm control matching the real [Mushroom cards](https://github.com/piitaya/lovelace-mushroom) look, house climate, and presence. Runs full-screen (e.g. on a wall-mounted tablet in kiosk mode) but also works fine as one card among others on a phone or desktop dashboard.

Two ways to install it: as a real **Lovelace custom card** via HACS (recommended — see below), or as a **standalone iframe** (the original deploy method, still supported).

## Using it for your own house

Everything about *your specific house* — room shapes, names, and which HA entities belong to which room — lives in **one file**, `src/house.config.json`. Nothing else in the app needs to change.

### The easy way: `tools/room-designer.html`

Open this file directly in any browser (no install, no server — just double-click it or drag it into a browser tab). It's a small visual editor:

1. **Upload a photo of your floor plan** (a phone photo of a paper plan, a screenshot from your home's building plans, whatever you have) to trace over it, or just draw freehand against the grid.
2. **Click-drag on the canvas** to draw a room as a rectangle. Drag its blue corner handle to resize it, or drag the room itself to move it.
3. Click a room (on the canvas or in the list) to **edit its name, color, and entities**:
   - **Home Assistant area name(s)** — if you've organized your HA entities into [Areas](https://www.home-assistant.io/docs/organizing/areas/), list the area name(s) that belong to this room (e.g. `Kitchen, Cocina` if you have entities in multiple languages/naming). The app will automatically pull in every entity HA has assigned to that area.
   - **Fallback entity IDs** — entities to always show in this room, regardless of their HA Area (or if you don't use Areas at all). Comma-separated `entity_id`s, e.g. `light.kitchen_main, switch.kitchen_fan`.
   - **Exclude patterns** — text that, if it appears in an entity's ID or name, hides it from this room even if it matched by area. Handy for excluding a baby monitor camera that happens to share a device/area with your bedroom lights, for example.
   - **Baby zone** — adds a "Clean baby zone" vacuum shortcut for this room (only meaningful if you use a robot vacuum integration with a defined baby-zone script — see below).
4. **Export house.config.json** when you're happy with the layout, and drop the downloaded file straight into `src/house.config.json`, replacing the example one.

Rooms only support simple rectangles for now (most real rooms are rectangular or close enough) — see "Limitations" below if yours genuinely isn't.

### The manual way: editing `house.config.json` directly

If you're comfortable hand-editing JSON, the schema is:

```jsonc
{
  "viewBox": { "width": 1184, "height": 1280 },   // overall canvas size, arbitrary units
  "drawOrder": ["corridor", "kitchen", "..."],     // paint order (later = on top, matters if shapes overlap)
  "roomOrder": ["kitchen", "living", "..."],       // display order elsewhere in the UI (People row, etc. are separate)
  "rooms": [
    {
      "key": "kitchen",                 // internal id, must be unique, used in drawOrder/roomOrder
      "name": "Kitchen",                // display name
      "roomId": 8,                      // only used if you wire up a robot-vacuum room-cleaning script (see below) - otherwise any number is fine
      "fill": "#dfe3ee",                // CSS color, or "url(#tiles)" for the built-in tile pattern (see Defs in Floorplan.tsx)
      "areaNames": ["Kitchen", "Cocina"],
      "fallbackEntities": ["light.kitchen_main"],
      "excludeEntityPatterns": ["camera"],   // optional
      "baby": false,                          // optional
      "fallbackOnly": false,                  // optional - true skips HA area-matching entirely, uses ONLY fallbackEntities
      "climateEntities": ["sensor.kitchen_temp"],  // optional - temperature/humidity/lux/co2 sensors shown as a badge on this room when zoomed in
      "climateEntity": "climate.kitchen_thermostat", // optional - a real climate entity for the Temperature control (omit to use local-only state)
      "coverEntity": "cover.kitchen_blinds",         // optional - a real cover entity for the Blinds control (omit to use local-only state)
      "d": "M70,91 L294,91 L294,378 L70,378 Z",  // SVG path (auto-generated by the designer tool from bx/by/bw/bh)
      "bx": 70, "by": 91, "bw": 224, "bh": 287,  // bounding box - drives the zoom transform + sensor badge position
      "dx": 100, "dy": 170,                       // small "lights on" status dot position
      "lx": 182, "ly": 270                        // room name label position
    }
  ]
}
```

`bx/by/bw/bh/dx/dy/lx/ly/d` are all in the same `viewBox` unit space — you basically never need to hand-write these if you use the designer tool, since it derives all of them from the rectangle you drew.

### Robot vacuum integration

The "Clean room" / "Clean baby zone" / "Clean whole house" buttons call HA scripts (`script.vacuum_clean_rooms` with a `room_id`, `script.vacuum_clean_baby_zone`, `script.vacuum_clean_all`) that you need to define yourself, matching whatever room-ID scheme your own vacuum integration uses (this project was built against a Xiaomi/Roborock-family integration where rooms are numbered). If you don't have a robot vacuum, or don't want this, remove the buttons in `App.tsx`'s "Cleaning" section instead of leaving `roomId` unused.

### Alarm panel

The alarm control expects a single `alarm_control_panel.*` entity supporting `disarmed` / `armed_away` / `armed_night` / `armed_vacation` states (matches the [Alarmo](https://github.com/nielsfaber/alarmo) integration exactly). Update `ALARM_ENTITY` in `App.tsx` to point at your own alarm entity. If your alarm integration exposes different modes, adjust `ALARM_MODES` accordingly.

### People / presence

`PEOPLE_ENTITIES` in `App.tsx` lists which `person.*` entities to show. Presence coloring reads real HA states (`home` / a named zone like `work` / `not_home` / `unknown`) — if you have HA Zones beyond just home, they'll show with their own icon and a blue tint automatically (no config needed beyond having the zone itself configured in HA with an icon).

## Responsive behavior

Three real size tiers:

- **Phone** (≤560px wide, portrait) — floorplan goes full-screen by default with a drag-out side panel.
- **Tablet** (the default/baseline styling, tuned against a 1024×600 wall-mounted tablet) — persistent side panel, no drawer.
- **Desktop** (≥1400px wide) — more generous panel width, larger text, more breathing room, rather than the tablet-tuned layout just being centered with dead space on either side.

If your own device doesn't fit neatly into one of these (e.g. a large tablet in portrait, or a very small laptop window), the tablet tier is the safe fallback — it's plain flexbox/grid underneath, so it degrades reasonably at in-between sizes even without a dedicated breakpoint.

## Installing as a Lovelace card (recommended)

This repo also ships as a real Lovelace **custom card** (`type: custom:housemap-card`) — a Home Assistant Web Component, not an iframe. It receives the live `hass` object Lovelace hands every card, so there's no access token to manage, no polling loop, and state updates arrive the moment HA pushes them rather than on a fixed interval. Its styles are fully isolated in a Shadow DOM, so it won't clash with any other card or dashboard theme.

**Via HACS** (not yet in the default HACS store — add it as a custom repository):

1. HACS → the ⋮ menu (top right) → **Custom repositories**
2. Paste this repo's URL, category **Plugin**, click Add
3. Find "House Map" in HACS and install it
4. HACS registers the resource automatically. Add the card to any dashboard:
   ```yaml
   type: custom:housemap-card
   ```
   (or use the visual card picker — it's listed as "House Map")

**Manually**, without HACS: download `housemap-card.js` from this repo (or a release) into `/config/www/`, add it as a Lovelace resource (Settings → Dashboards → ⋮ → Resources → Add Resource, JS Module, URL `/local/housemap-card.js`), then add `type: custom:housemap-card` to a dashboard the same as above.

Either way, **the house layout still comes from `src/house.config.json`** at build time (see above) — the card ships pre-built against whichever house's config was checked in when it was last built. To point it at your own house, use `tools/room-designer.html` to produce your own `house.config.json`, drop it in, and rebuild:

```bash
npm install
npm run build:card   # tsc --noEmit && vite build --config vite.card.config.ts, produces dist-card/housemap-card.js
```

Then replace the committed `housemap-card.js` with your rebuilt one (if you're maintaining your own fork) or just serve your own rebuilt file manually as above.

## Alternative: standalone iframe (the original deploy method)

Before the Lovelace-card packaging above existed, this app was deployed as a fully standalone site iframed into a dashboard, authenticating itself with a long-lived access token rather than receiving `hass` from Lovelace. This still works and is a reasonable choice if you'd rather not touch Lovelace resources/HACS, or want to self-host it somewhere outside `/config/www` entirely.

```bash
npm install
npm run build      # tsc --noEmit && vite build, produces dist/
```

Copy `dist/index.html` + `dist/assets/*` to wherever your HA instance serves static files from (typically `/config/www/<some-folder>/`, reachable at `/local/<some-folder>/index.html`). Add a `config.js` alongside `index.html` (not built by Vite, deliberately excluded from the bundle) containing your HA long-lived access token:

```js
window.HOUSEMAP_HA_TOKEN = 'your-long-lived-access-token';
```

Embed it in a Lovelace dashboard via an iframe card, e.g.:

```yaml
type: custom:html-card   # or a plain iframe card if you don't use html-card
content: |
  <iframe src="/local housemap/index.html" style="width:100%;height:100vh;border:0"></iframe>
```

If you edit `house.config.json` or any source file after the dashboard is already loaded somewhere, remember that browsers cache aggressively — bump a `?v=` query param on the iframe's `src` (or your kiosk browser's own cache-purge setting) to force a fresh load.

## Limitations / things a future contributor could improve

- Rooms are axis-aligned rectangles only — an L-shaped room needs to be approximated as one rectangle, or you can hand-edit the `d` path afterward for an exact shape (the designer tool won't touch a `d` you've customized as long as you don't re-drag that room's handles).
- The designer tool doesn't do anything with `drawOrder` beyond "the order you drew rooms in" — if two rooms' rectangles overlap, reorder them in the exported JSON by hand if the wrong one paints on top.
- No import validation — if you hand-edit `house.config.json` into something malformed, you'll find out at `npm run build` (TypeScript will complain) rather than get a friendly error.
- The Lovelace card's house layout is baked in at build time (from `src/house.config.json`), not configurable per-install from the dashboard YAML — a different house needs its own rebuilt `housemap-card.js` today, same as the standalone build. A `config_url` (fetch a house config at runtime instead of bundling one) would remove that requirement but doesn't exist yet.
- Not in HACS's default/searchable store yet — installable today only by adding this repo as a HACS **custom repository** (see above), which works identically once added but isn't discoverable without the URL. A submission to [hacs/default](https://github.com/hacs/default) is open and in the review queue.
